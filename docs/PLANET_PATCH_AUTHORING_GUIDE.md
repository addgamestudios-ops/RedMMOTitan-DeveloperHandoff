# RED 27-map terrain authoring guide

## Current status

The 27 square maps are now real editable source rasters and can be fused into six seam-safe
PlanetGen cube faces. The current playable Unreal map does **not** consume those faces yet.
Unreal import, isolated-map assignment, collision, water, and traversal approval remain pending.

The authoring command is fail-closed: running it without a command does nothing and returns an
error. Manual source maps are never regenerated by `bake-existing`.

## One-time baseline snapshot

Before painting anything, capture the currently accepted source revision:

```powershell
python Tools\generate_planet_authoring_patches.py snapshot-sources
```

The verified initial snapshot is:

```text
SourceArt/Planet50Km/AuthoringPatches/RevisionBackups/
  APPROVED_SOURCE_81F1E8E9D1C25BB8E9CF1D4E17423B2D81AF0DFE839CADEBB5569F408CBF75B6
```

Snapshots are content-addressed and contain the source manifest plus all 135 patch files.

## What each square contains

For patch `00` through `26`, edit only its five canonical files in
`SourceArt/Planet50Km/AuthoringPatches`:

| File | Format | Meaning |
|---|---|---|
| `RED_Patch_XX_Height_16.png` | grayscale 16-bit PNG | preferred editable height source |
| `RED_Patch_XX_Height.r16` | little-endian uint16 | derived Unreal/import companion |
| `RED_Patch_XX_Land.png` | grayscale L8 | land/water intent; normally 0 or 255 |
| `RED_Patch_XX_Biomes.png` | RGBA8 | R desert, G temperate, B cold/mountain, A alien |
| `RED_Patch_XX_Authority.png` | grayscale L8 | soft protected ownership during overlap |

Height is linear: sample `0` is -30,000 cm and `65,535` is +30,000 cm relative to the
planet datum. Sea level is currently 0 cm. Preserve grayscale 16-bit mode; do not use palette,
gamma, color-profile, or lossy conversion.

The current accepted blockout rasters are 257 x 257. The profile records 513 x 513 as the next
target resolution, but strict bake and edit acceptance intentionally derive their resolution
from the accepted raster manifest. Do not resize individual patches. Resolution migration must
replace all 27 maps as one reviewed revision.

## Orientation and overlap

- Image right is local east (`+U`).
- Image top is local north; rows increase south.
- The full source square represents 8.000 km.
- The full-authority authored core is 5.4289168 km.
- Each edge has a 1.2855416 km cubic feather, about 41 pixels at 257 x 257.
- Keep coastlines, hubs, cliffs, and other hard landmarks inside the core when possible.
- Continue terrain naturally through the feather instead of painting a hard square border.
- Authority 255 can prefer one patch by up to 256x, but it remains a soft normalized blend.
  It is not a wall, collision mask, streaming cell, or PCG/manual-placement reservation.

Effective overlap weight is:

```text
edge smoothstep x angular center kernel x 2^(priority + 8 x authority)
```

All active contributions are normalized, so source-square borders never become gameplay borders.

## Safe single-patch practice

1. Run `snapshot-sources`.
2. Start with `RED_Patch_13_Biomes.png`; patch 13 is near the equator and is a useful practice
   square. Paint a small biome variation well inside the core without changing dimensions or mode.
3. Optionally paint the same protected area softly into `RED_Patch_13_Authority.png`. Fade it
   before the feather band.
4. Accept the edit and bake:

```powershell
python Tools\generate_planet_authoring_patches.py accept-edits
```

5. Repeat the strict bake to prove determinism and ensure it cannot change source art:

```powershell
python Tools\generate_planet_authoring_patches.py bake-existing
```

Acceptance fails before publication if any file has the wrong dimensions/mode, a source is
missing, coverage has a hole, source provenance is malformed, or an encoded cube edge differs.
The face bake is staged and the manifest is published last; the previous complete derived face
revision is retained under `MacroFacesFromPatches/RevisionBackups`.

`accept-edits` validates its face output and resolution before accepting source bytes. If the
later face bake fails, it restores the pre-accept source revision. `restore-snapshot` applies the
same rule to the pre-restore revision. Both rollback paths refuse to overwrite a newer editor save
that appears during the command.

## Height conflict handling

In normal use, edit the 16-bit PNG and leave R16 alone. `accept-edits` detects the changed PNG,
validates every patch first, snapshots the current source bytes, and synchronizes the derived R16.

If R16 changed by itself, or PNG and R16 disagree after both changed, automatic acceptance stops
without overwriting either edit. Resolve explicitly:

```powershell
# Keep the PNG and regenerate R16.
python Tools\generate_planet_authoring_patches.py accept-edits --height-source png

# Keep R16 and regenerate the 16-bit PNG.
python Tools\generate_planet_authoring_patches.py accept-edits --height-source r16
```

The accepted manifest records the parent hashes, selected height source, sorted file changes, and
pre-accept snapshot. Repeating acceptance with no changes leaves the manifest byte-identical.

## Restore the approved blockout

Restoration first snapshots the current work, validates the selected complete revision, restores
all 135 files plus its manifest, and then rebakes the six faces:

```powershell
python Tools\generate_planet_authoring_patches.py restore-snapshot `
  --snapshot APPROVED_SOURCE_81F1E8E9D1C25BB8E9CF1D4E17423B2D81AF0DFE839CADEBB5569F408CBF75B6
```

Do not use `git clean`, whole-tree deletion, or broad restore commands for one terrain edit.

## Analytic reset is deliberately destructive

`initialize-blockout` is the only mode that can regenerate all 27 source maps. It refuses any
existing source artifact unless the destructive intent is explicit:

```powershell
python Tools\generate_planet_authoring_patches.py initialize-blockout `
  --force-overwrite-existing-sources
```

This is not the normal editing command. It creates a pre-initialize backup first.

## Runtime promotion gate

Do not promote a source revision to the production map based only on offline success. The importer
and first isolated runtime height capture now pass; the remaining promotion order is:

1. edit and accept source squares, then rerun the authenticated import into the isolated
   macro-heightfield asset;
2. assign only `RedPlanetGen_50km_FusedPrototype`; keep production and
   `RedPlanetGen_50km_Test` as rollback points;
3. compare rendered terrain and collision;
4. add and verify Unreal/runtime consumers for the persisted land and biome masks;
5. verify ocean datum and biome queries;
6. walk and fly across patch and cube-face seams with no wall, teleport, hole, or hitch; and
7. preserve all rollback-map hashes before any production promotion.
